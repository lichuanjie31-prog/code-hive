# 本地文章管理页设计

## 目标

为 code-hive 提供一个只在本机开发环境开放的文章管理页。仓库所有者可以在网页中新增、查看、编辑和删除文章，使用 Markdown 写正文，上传封面与正文插图，并实时预览正式文章效果。保存后直接更新仓库里的 Markdown、图片和文章索引。生产构建不提供任何写入能力。

## 使用流程

运行 `npm run dev` 后访问 `#/admin/articles`。管理页左侧展示文章列表和搜索，中间编辑 Markdown，右侧实时预览。顶部编辑标题、摘要、作者、日期、slug 和封面。

新建文章时，系统根据标题生成 slug，用户可以修改。上传正文图片后，文件写入该文章的独立图片目录，编辑器在光标位置插入带替代文本的 Markdown 图片语法。点击保存后，页面先完成字段与引用校验，再调用本地接口写入文件。保存成功后刷新列表和预览。

编辑现有文章时，管理页读取索引、Markdown 和图片信息。删除文章时显示标题并二次确认，只删除正文文件、索引记录和该文章专属图片目录。

## 架构

### 管理页面

管理页面沿用现有 React 应用与 Hash 路由。它包含文章列表、元数据表单、Markdown 编辑器、图片选择控件、操作反馈和实时预览。正式文章页与管理预览共用 Markdown 渲染组件，避免预览样式与上线效果分离。

管理入口只在开发模式显示。直接访问生产环境中的管理地址时，页面显示不可用提示，不渲染编辑器，也不尝试调用写入接口。

### 本地写入服务

在 Vite 开发服务器中注册仅限开发模式的本地 API。服务绑定 `127.0.0.1`，处理文章读取、保存、图片上传和删除。生产构建不注册这些路由，也不包含可执行的服务端写入代码。

API 所有文件路径都从受控 slug 和固定目录计算。客户端不得提交任意磁盘路径。服务拒绝包含路径分隔符、点号跳转或不符合规则的 slug，所有最终路径都必须位于 `src/content/articles`、`public/articles` 或 `src/data/articles.js` 允许范围内。

### 数据与文件布局

文章索引继续使用 `src/data/articles.js`，保留现有字段和 URL。正文保存在 `src/content/articles/<slug>.md`。文章图片集中放入 `public/articles/<slug>/`，其中封面采用固定文件名，正文图片保留经清理的文件名并处理重名。

已有文章保持原 URL。第一次在管理页保存旧文章时，可以继续引用原图片；新上传图片进入文章专属目录。删除操作只清理专属目录，旧的共享图片不自动删除，避免影响其他文章。

## 保存与错误处理

保存前检查必填字段、日期格式、slug 格式与唯一性、正文长度、图片替代文本和本地图片引用。编辑文章时允许保留原 slug；修改 slug 需要确认，因为文章 URL 会变化。

写入采用先生成完整目标内容，再写临时文件，校验成功后替换正式文件的顺序。正文与索引任一写入失败时，接口返回明确错误，页面保留当前输入。上传失败不插入 Markdown。删除失败时保留索引记录，并显示未完成的文件操作。

管理页用固定状态显示保存中、已保存、校验失败和服务不可用。页面离开前若有未保存改动，触发浏览器确认。

## 安全边界

本地 API 只接受来自同一开发服务器的请求，并校验请求来源。请求体和图片大小设置上限，只允许常见图片 MIME 类型。文件名经过清理，拒绝路径越界。删除接口要求客户端提交文章 slug 和二次确认标记，服务端再次确认文章存在。

管理功能不引入登录、数据库、云端上传和生产写入接口。局域网设备无法通过默认启动方式访问管理服务。用户若手动修改开发服务器监听地址，服务仍拒绝非本机来源的写入请求。

## 测试与验收

自动测试覆盖文章列表读取、新建文章、编辑正文与元数据、上传封面和插图、重复 slug、非法 slug、路径越界、图片类型与大小限制、删除确认、原子写入失败以及生产模式无写入 API。文件操作测试使用临时目录和真实文件，不替换被测逻辑。

浏览器验收覆盖现有两篇文章载入、Markdown 实时预览、上传图片后自动插入语法、新建并保存文章、重新打开后内容一致、编辑保存、删除二次确认、未保存离开提醒和移动端可用性。

最终运行 `npm test`、`npm run lint` 和 `npm run build`。生产产物中不得出现文章写入端点，现有两个文章 URL 与 14 条资源必须保持可用。
